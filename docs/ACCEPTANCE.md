# Acceptance and test matrix

| Area | Expected outcome | Verification |
|---|---|---|
| Startup | WebGL starts without uncaught JS errors | Automated browser test and manual |
| Movement | W forward, A left, D right; intuitive mouse and touch look | Manual desktop/mobile |
| Weapon | Shooting consumes ammo; pause blocks fire; reload uses reserve | Browser test |
| Objectives | Three nodes can be disabled; extraction requires all three | Browser test and walkthrough |
| Win/lose | Extraction wins, zero HP fails, restart resets everything | Browser test |
| AI | Guards react and navigate without phasing through geometry | Manual walkthrough |
| Mobile | Landscape joystick/look/fire/reload/interact/pause | Emulator and physical device |
| Graphics | Believable models/materials, lights, wet ground; no large clipping errors | Running-game screenshots |
| Performance | Hardware, resolution, FPS and memory measured | Recorded metrics |
| Licensing | Provenance and allowed-use rights documented | Asset audit |

**Status rules:** "Implemented" means code exists, "tested" means tests actually ran, and "accepted" means the milestone passed on target hardware.

## Real-hardware checklist (nothing below has been done; record device, OS / browser version, preset, resolution and result)

**iPhone Safari (landscape, add to Home Screen optional)** and **Windows Chrome / Edge** (discrete and integrated GPU if possible):
1. Load `/game/` (iPhone: from a computer on the same network, e.g. `python3 -m http.server` or `serve.ps1`; Windows: `serve.ps1`). Confirm the menu starts without a "Kunde inte starta grafiken" message and that `?perf=1` shows the GPU name.
2. **FPS per preset**: with `?perf=1`, play each of `?q=low`, `?q=medium`, `?q=high` for at least 2 minutes (spawn view, Node A fight, the long route to Node C, extraction). Write down average FPS, worst frame (ms), resolution and draw calls shown in the overlay. On iPhone also note thermal throttling after 10 minutes and whether the page reloads (memory).
3. Console / Web Inspector: no shader errors. If the game says it switched to lite shading (console warning "shader program failed to compile / link"), record the device and the log: that is exactly the finding the shader audit cannot give. Optionally run `tools/shader_audit.js`-style checks via `?qa=1` pages on a desktop with the same GPU.
4. Compare `?q=low` (lite) with `?q=low&lite=0` on the same device: frame time and whether anything visible is lost.
5. **Radio voices**: play until the comrades call out; judge intelligibility, volume against gunfire, the squelch click / static / tail, and whether Swedish speech voices exist on the device (browser speech is the only voice source; on iOS it may be silent until a user gesture, on Windows it depends on the installed voices). Check there are no remaining rain-loop artefacts.
6. **Close-up soldiers**: stand 1-3 m from a guard and a comrade (idle, walking, aiming, hit, death). Check faces / eyes / hair, balaclava, uniform folds and seams, gloves and boots, the first-person arms in hip and ADS, foot planting (no skating), and that nothing flickers or shimmers (specular aliasing on the ripstop / twill, banding in dark areas).
7. A complete mission by hand (3 nodes, extraction, pause, restart, defeat) with mouse / keyboard on Windows and touch controls on the iPhone (joystick direction not mirrored, look, fire, reload, use).
8. Fill in the FPS table in this file and only then discuss moving M1 / M2 / M3 to accepted.

**Known gaps:** soldiers still read as game characters rather than photographs at 1-2 m (uniform fabric is procedural: the ripstop grid and twill only resolve on the first-person sleeves or within ~0.5 m, joint folds are a shader relief on an unchanged silhouette, seams are placed from body segments rather than real garment panels; MakeHuman anatomy now, but clothing is an offset skin with displaced folds, not simulated or sculpted cloth; balaclava knit relief is procedural (shader), not modelled; boot toe caps are reshaped analytically but the coarse toe topology still leaves faint shading facets; no wrist / forearm twist bones (the hand / forearm weight blend is only spread over ~9 cm), so extreme wrist rotation can still pinch; short hair is a single shell with shader strands (no real strand geometry), and its hairline fade is about 1-1.5 cm; skin pores are below a pixel beyond ~0.5 m, so faces still read as CG at 1 m (MakeHuman face shape, no scanned albedo); the left hand still sits ~1 cm below the handguard, so its fingers wrap beside it rather than gripping it; lenses use a stylised not captured reflection); software-GPU screenshots only; no real-device FPS; soldiers are procedural skinned meshes (not scanned/photographic); AI navigation unchanged from v0.1; comrades are invulnerable and do not take part in objectives; heavy frame cost before the performance pass (641 calls / 5.1 M tris per frame at medium, all passes).
